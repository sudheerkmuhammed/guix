\epigraph{``Time travel used to be thought of as just science fiction, but Einstein's general theory of relativity allows for the possibility of warping spacetime... and GNU Guix implemented it in Scheme.''}{--- Stephen Hawking (paraphrased by a Guix hacker)}

\noindent
In standard Linux distributions, the concept of ``updating your packages'' is a one-way street into the unknown. When you type \texttt{apt update}, you fetch whatever package definitions happen to be on Debian's mirrors right now. If a scientist wrote code against Python 3.8 and Scipy 1.4 in 2020, attempting to run that same code on an updated 2026 system will usually result in an avalanche of syntax errors, deprecated APIs, and broken wheels.

In GNU Guix, the package collection itself is versioned as a Git repository. Updating Guix is not a chaotic roll of the dice; it is a tracked, reproducible Git checkout called a \textbf{Channel}.

\section{The Heartbeat: \texttt{guix pull}}

To update your Guix package definitions and the \texttt{guix} binary itself, you run:

\begin{lstlisting}[style=guixcli]
guix pull
\end{lstlisting}

Unlike \texttt{apt update} (which merely downloads package indices), \guixcmd{guix pull} downloads the latest Guile Scheme source files from the official Guix Git repository, verifies their cryptographic OpenPGP signatures against a trusted keyring, compiles the Scheme modules with GNU Guile's optimizing byte-compiler, and creates a new generation of your Guix tool itself!

\begin{alchemybox}[Channel Authentication \& The OpenPGP Web of Trust]
How do you know an attacker hasn't compromised the Guix Git repository and injected malicious package recipes?
Guix includes built-in OpenPGP authentication. Every commit in the official Guix channel must be signed by an authorized maintainer. When you run \guixcmd{guix pull}, Guix verifies the signature chain all the way back to the channel's historic ``introduction commit''. If an unsigned or unauthorized commit is pushed, \guixcmd{guix pull} refuses to execute it.
\end{alchemybox}

\section{The Separation of Church and State: Free vs Custom Channels}

The official GNU Guix repository adheres strictly to the \textbf{GNU Free System Distribution Guidelines (FSDG)}. This means the default Guix channel will never contain proprietary binary blobs, non-free firmware, or software with restrictive licenses.

However, in the real world:
\begin{itemize}
  \item Your laptop might have an Intel or Broadcom Wi-Fi chip that stubbornly refuses to transmit radio waves without proprietary microcode firmware.
  \item Your research laboratory might require proprietary GPU drivers (like NVIDIA CUDA) or specialized scientific simulators.
  \item You might want to relax after a long day of functional programming by playing games on Steam.
\end{itemize}

Because Guix channels are completely decentralized, the community maintains powerful, curated third-party channels that integrate smoothly with your system.

\section{Notable Community Channels in the Wild}

Let us explore the most famous and widely used custom channels in the Guix ecosystem:

\subsection{1. Nonguix: The Unofficial Non-Free Repository}

\textbf{Nonguix} is the essential channel for desktop and laptop users who need hardware compatibility with proprietary firmware and non-free software.

It provides:
\begin{itemize}
  \item The vanilla \textbf{\texttt{linux}} kernel (with non-free binary blob drivers) and \textbf{\texttt{linux-firmware}} for Intel, AMD, Realtek, and Broadcom Wi-Fi/Bluetooth.
  \item Proprietary desktop applications: \textbf{Steam}, \textbf{Spotify}, \textbf{Google Chrome}, \textbf{Discord}, and \textbf{Visual Studio Code}.
  \item The \textbf{NVIDIA} proprietary graphics driver stack.
  \item Pre-built binary substitutes hosted on a dedicated build farm (\url{https://substitutes.nonguix.org}).
\end{itemize}

\subsection{2. Guix Science \& Guix HPC: High-Performance Research}

Maintained by research institutions including Inria, the Max Delbr\"uck Center, and academic high-performance computing centers, \textbf{Guix Science} extends Guix with specialized computational research software:

\begin{itemize}
  \item \textbf{Bioinformatics \& Genomics}: High-throughput sequencing pipelines, Bioconductor packages, and bioinformatics CLI tools.
  \item \textbf{Machine Learning \& AI}: Accelerated PyTorch, TensorFlow, JAX, CUDA/ROCm bindings, and optimized BLAS/LAPACK implementations.
  \item \textbf{HPC \& Clusters}: SLURM integrations, OpenMPI fabrics, and parallel simulation toolkits.
\end{itemize}

\subsection{3. Guix Past: The Museum of Computational History}

Have you ever tried running a 15-year-old computational biology script that strictly requires GCC 4.8, Python 2.7, and an obsolete version of Autotools that fails to build on modern Linux?

\textbf{Guix Past} packages historic software stacks using modern Guix packaging standards. It allows researchers to resurrect legacy environments with 100\% mathematical fidelity.

\section{Configuring Multiple Channels in \texttt{channels.scm}}

To use these community channels, you declare them in your \texttt{\textasciitilde/.config/guix/channels.scm} file:

\begin{lstlisting}[style=guixscheme]
;; ~/.config/guix/channels.scm
(use-modules (guix ci))

(list
  ;; 1. The official GNU Guix Channel
  (channel
    (name 'guix)
    (url "https://git.savannah.gnu.org/git/guix.git")
    (branch "master")
    (introduction
      (make-channel-introduction
        "9edb3f66fd80fdac9e8b0f7b442a030d125b6dd7"
        (openpgp-fingerprint
          "BBB0 2DDF 2CEA F6A8 0D1D  E643 A2A0 6DF2 A33A 54FA"))))

  ;; 2. Nonguix Channel (Non-free firmware, Steam, Spotify, Linux kernel)
  (channel
    (name 'nonguix)
    (url "https://gitlab.com/nonguix/nonguix")
    (introduction

        "2a97032c462432673b8cdab8598463e8006e8b4e"

          "2A39 3FFF 68F4 EF7A 3D29  12AC 040F D0D4 8845 7307"))))

  ;; 3. Guix Science Channel (PyTorch, Bioinformatics, HPC)

\begin{protipbox}[Authorizing the Nonguix Substitute Server]
To avoid compiling the Linux kernel or Chromium from source, authorize the Nonguix pre-built binary substitute server:
\begin{lstlisting}[style=guixcli]
# Download and authorize Nonguix's signing key:
guix archive --authorize < /path/to/nonguix-signing-key.pub

# In your /etc/config.scm or guix-daemon flags, add the substitute server:
# https://substitutes.nonguix.org
\end{lstlisting}

\section{Real-World Examples: Using Nonguix \& Guix Science}

Once you run \guixcmd{guix pull} with the channels above, your package universe expands instantly:

\subsection{Example A: Launching Steam or Spotify with Nonguix}

\begin{lstlisting}[style=guixcli]
# Install Spotify and Steam into your user profile
guix install spotify steam

# Or launch Steam inside a disposable container
guix shell --container --network --expose=/dev/dri steam -- steam
\end{lstlisting}

\subsection{Example B: High-Performance Data Science with Guix Science}

Suppose you need a Python environment with PyTorch and CUDA support for machine learning:

\begin{lstlisting}[style=guixcli]
# Spawn a pure shell with PyTorch from Guix Science
guix shell --pure python python-pytorch python-torchvision -- python3 -c "
import torch
print('CUDA Available:', torch.cuda.is_available())
print('PyTorch Version:', torch.__version__)
"
\end{lstlisting}

\section{Capturing Your Exact State: \texttt{guix describe}}

How do you communicate the exact state of your multi-channel operating system to a colleague?

You run:

\begin{lstlisting}[style=guixcli]
guix describe -f channels
\end{lstlisting}

This produces an exact, machine-readable Scheme file representing the precise Git commit hashes of all active channels (\texttt{guix}, \texttt{nonguix}, \texttt{guix-science}).

If you commit that output to a file named \texttt{channels.scm}, anyone can reproduce your multi-channel universe down to the exact bit using \guixcmd{guix time-machine}.

\section{The Superpower: \texttt{guix time-machine}}

Now comes the coup de gr\^ace that makes every other package manager look like an antique.

Suppose you have a \texttt{channels.scm} file containing pins for GNU Guix and Guix Science from three years ago. You want to re-run an experiment today:

\begin{lstlisting}[style=guixcli]
# Run an ad-hoc shell using the exact multi-channel universe from channels.scm
guix time-machine -C channels.scm -- shell python-pytorch r-ggplot2 -- python3 pipeline.py

# Or travel to a specific historic commit on the fly!
guix time-machine --commit=a84ef2b9d3... -- install emacs
\end{lstlisting}
